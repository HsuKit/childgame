- 底部导航固定为 4 个一级入口：冒险、伙伴、奖励、营地；子路由能正确高亮所属入口。

- 图标按钮具备可访问名称；年级、答题选项和主要操作满足至少 44px 触控高度。
- 正确、错误、进行中和完成状态同时使用图标与文字，不只依赖颜色。
- 弹窗使用 `aria-modal`、可访问标题、显式关闭/取消操作、`z-[70]` 和底部安全区。
- 全局 CSS 与动画组件支持 `prefers-reduced-motion`。
- 页面最大宽度和断点布局支持手机、平板与桌面；浏览器检查未发现横向滚动。

## 2026-07-30 伙伴与愿望回归修正

用户验收发现伙伴动画/收藏图片损坏，以及愿望查询失败时错误面板过重。根因分别是 canvas 在图片完成解码前调用 `drawImage`、收藏缩略图写死并非所有角色都存在的 blink 第 000 帧，以及愿望页没有把 fallback catalog 明确限制为只读。

修正后的自动化结果：

| 检查 | 结果 |
| --- | --- |
| 伙伴资源、动画、缩略图与愿望失败态专项 | 4 个测试文件、11 项测试通过 |
| Vitest 全量测试 | 29 个测试文件、145 项测试通过 |
| TypeScript + Vite 生产构建 | 通过 |
| 文档与差异检查 | 通过 |

浏览器使用新的匿名用户，不创建伙伴或提交愿望：

- `/companion/select` 首轮检查确认三位初始伙伴资源都能完成解码且页面无横向溢出；随后逐图复核发现 `Body.png` 只是身体零件，因此最终缩略图与静态兜底改用完整 idle 第 000 帧。仓库扫描确认所有配置 variant 的该帧均存在。
- 当前匿名用户尚无伙伴，因此 `/companion` 主画布没有通过写入真实伙伴数据验收；旧外观回退、broken image 不进入 canvas、完整静态兜底，以及动画接管后隐藏兜底避免残影，均由组件测试覆盖。
- `/wish-shop` 实际请求失败后显示“数据暂未同步”，继续展示默认目录；fallback 卡片具有禁用语义并显示“同步后可申请”，没有提交弹窗入口。
- “重新同步”会再次进入加载状态；再次失败后恢复相同只读提示。
- 上述流程控制台没有错误；没有再出现 `InvalidStateError: drawImage`。
