## 背景与目标

伙伴触摸、打卡月历、首页统计和答题 store 中已有改动需要补齐并发、日期、错误和重复逻辑边界。本记录于 2026-07-28 根据设计、实施计划和对应 Git diff 回填，描述的是 2026-07-20 完成的阶段，不代表当前代码现状。

## 范围

范围限于 `InteractiveCompanion`、`CheckInPage`、`HomePage`、`quizStore` 及为它们抽取的日期和答题纯函数、测试与测试脚本。包含伙伴输入与清理、月历查询、首页初始化、普通练习和每日挑战的启动、判题、统计与记录保存；不包含数据库结构或 RLS、奖励的数据库级幂等方案、其他 store 重构，也不包含后来发生的愿望、排行榜或 PK 修复。

## 实施摘要

- 伙伴交互统一到 Pointer Event，并补充键盘入口、稳定的特效 ID、创建时固定的图标和卸载时计时器清理，避免一次触摸重复触发和卸载后遗留计时器。
- 打卡月历改用本地日期工具，月份移动固定落到目标月首日；查询以请求序号守卫，过期响应和卸载后的响应不会覆盖最新月份，并提供独立加载、失败提示和未来月份限制。
- 首页把伙伴、签到、积分初始化并行触发；今日答题统计只受已认证用户 ID 守卫，不再等待伙伴数据。统计失败保留零值，effect 清理阻止卸载后写入，挑战奖励文案与当时结果页的 200 分保持一致。
- 普通练习和挑战复用判题、连击奖励及 Fisher–Yates 洗牌；启动流程用 `try/finally` 保证结束加载，Supabase 查询错误向调用方传播。今日统计使用本地日界的起止时间并合并学科计数与挑战状态；结算记录过滤前端生成题后批量插入并检查写入错误。

## 决策与原因

将日期边界、判题、计分、洗牌和统计聚合抽成纯函数，使页面和 Zustand store 只承担状态及 Supabase 编排，也让月末、跨年、本地日界和连击封顶能由单元测试固定。初始化和异步回调使用用户/profile 前置条件、请求序号、effect 活跃标记与 `try/finally` 组合守卫，以避免未满足依赖时启动、旧请求覆盖新状态或加载永久不结束。

## 验证结果

提交 `55be6cb` 中可确认新增 `src/lib/dateUtils.test.ts` 与 `src/lib/quizUtils.test.ts`：覆盖月末及跨年移动、本地日期与日界、题型判定、连击封顶、不可变洗牌和未知学科聚合；同一提交还加入 Vitest 测试脚本。仓库没有保留 2026-07-20 当时运行测试或构建的原始日志，因此不把计划中的预期命令写成已执行事实。2026-07-28 回填时，文档校验测试 21/21、仓库文档检查、链接检查和 `git diff --check` 均通过；这些只验证本次文档回填。

## 风险与遗留

该阶段明确没有解决奖励或记录写入的数据库级幂等与事务边界，重试仍可能重复结算。前端生成的数独题在保存时被过滤，完成题数与持久化记录可能不一致；这属于当时已知边界，后来题库改造不应倒算为本阶段成果。首页失败时采用零值降级而非向用户展示细分错误，月历重试也依赖再次切换月份。没有保留完整历史验证日志。
