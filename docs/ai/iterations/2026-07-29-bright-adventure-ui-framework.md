## 背景与目标

原界面按功能逐页生长，颜色、卡片、按钮、加载态和返回方式缺少统一规则，底部同时放置六个一级入口，学习主线不突出。本迭代目标是建立面向小学阶段的“明亮冒险”框架，把一级导航收敛为冒险、伙伴、奖励、营地四项，并统一首页、标准内页、专注流程和结算体验。

## 范围

包含设计令牌、共享 UI 原语、路由元数据、应用壳、四入口导航、地图首页，以及认证、答题、挑战、结果、伙伴、商城、愿望、排行榜、营地、打卡、家长、PK 和错题页面的呈现重组。保留现有路由参数、store、Supabase 表/RPC、购买、答题、结算和状态转换业务语义。

不包含数据库迁移、题库内容变化、排行榜/PK 的既有 RLS 修复、结算事务化、路由级代码分割或创建真实后端验收数据。

## 实施摘要

- 新增明亮冒险语义颜色、排版、间距、焦点、触控与 reduced-motion 规则。
- 新增 `Button`、`Surface`、`PageHeader`、`ProgressBar`、`StatePanel` 等跨域 UI 原语。
- 用路由元数据区分标准壳与专注壳；底部导航由六项收敛为冒险、伙伴、奖励、营地，并新增 `/rewards` 聚合入口。
- 首页重建为每日冒险地图，保留三科、挑战、错题、PK、伙伴和愿望进度入口。
- 统一答题题卡、正误解释、结果结算状态；普通与挑战结算增加失败重试。
- 重组伙伴/衣柜、奖励/愿望/排行榜、营地/打卡/家长、PK/错题和认证/覆盖层页面。
- 弹窗统一可访问标题、显式关闭、`z-[70]` 与 safe-area；动画支持减少动态效果。

## 决策与原因

- 采用“地图首页 + 标准内页”，让首页承担儿童冒险感，其余数据和管理页面保持清晰稳定。
- 把六个底部入口合并为四个一级目的地，降低移动端识别与点击负担；商城归入伙伴，愿望与排行榜归入奖励，打卡和家长工具归入营地。
- 数据依赖路由没有通过伪造登录态或写入真实后端来完成浏览器验收，避免产生测试用户、积分、愿望或 PK 数据。

## 验证结果

- `npm test`：25 个测试文件、134 项测试通过。
- `npm run test:questions`：86 项 Node 测试通过。
- `npm run questions:validate`：1–6 年级 2520 道 canonical 题目可发布。
- `npm run build`：TypeScript 与 Vite 生产构建通过。
- 浏览器检查：375×812、768×1024、1024×768 无横向溢出；手机交互目标 48–56px；关键匿名路由守卫、表单联动和控制台错误检查通过。
- 完整命令与限制见 [QA 记录](../../qa/2026-07-29-ui-route-regression.md)。

## 风险与遗留

- 普通/挑战结果页虽然增加可见重试，但多步写入仍不是数据库事务，部分成功后的重试仍需幂等保护。
- `check_ins.challenge_done` 的迁移/类型缺口和本地/UTC 日期不一致未在本迭代修复。
- PK 对手回写 RLS、challenge 级会话隔离、双方同题与排行榜跨用户 RLS 风险保持不变。
- 伙伴/商城购买仍是先扣积分再更新伙伴的客户端串行步骤。
- 生产包超过 500 kB，后续可做路由级代码分割。
