# 全国通用小学题库系统设计

## 1. 目标与范围

本阶段为一至六年级建设全国通用、无教材版本绑定的语文、数学、英语静态题库，并改造运行时组卷逻辑。用户答题时只访问 Supabase 中已经审核的题目，不调用任何大模型或外部生成服务，因此不会产生实时 AI Token 成本。

第一阶段每个年级 420 题，共 2,520 题；每个年级三科各 140 题。题库通过离线流程生成、审校、导入和版本管理。完成真实使用验证后，可沿用同一规则将每个年级扩充到 840 题。

本阶段包含：

- 一至六年级三科知识蓝图和题量配额。
- 统一的题目数据格式和数据库元数据。
- 离线校验、统计、SQL 生成和安全导入流程。
- 基于题型、难度、知识点与作答历史的动态组卷。
- 现有题库的审计、二年级优质题目的迁移和重复题清理。

本阶段不包含：

- 用户答题过程中的 AI 实时出题。
- 与某一出版社、教材单元或学期进度绑定。
- 自动判定自然语言长答案、作文或口语录音。
- 后台可视化题库编辑器。

## 2. 已确认的选择

采用“仓库中的标准题库 JSON 是唯一内容源，Supabase 是发布后的运行副本”的方案。与仅在数据库中手工维护相比，它可审查、可测试、可回滚；与运行时模板或 AI 生成相比，它能保证题目质量稳定且没有用户侧生成成本。

所有题目进入数据库前必须通过确定性校验。题目变更由内容哈希识别，导入采用幂等 upsert，不再执行“先删除全部 builtin 再插入”的危险流程。旧的在线 AI 出题函数不参与任何用户答题路径。

## 3. 课程蓝图

知识蓝图依据教育部 2022 年义务教育课程方案和课程标准体现的核心素养、学段衔接及真实情境应用原则制定。蓝图只定义年级适切的能力边界，不复制教材章节顺序。

### 3.1 语文

| 年级 | 核心知识与能力 |
| --- | --- |
| 一年级 | 拼音与音节、常用字识读、词语搭配、简单句、标点初步、短文显性信息、生活表达 |
| 二年级 | 字音字形、近反义词、量词与搭配、句式转换、句子排序、段落信息提取、古诗名句与生活语言运用 |
| 三年级 | 语境词义、病句初步、段落结构、修辞初步、人物事件与中心信息、应用文常识、传统文化积累 |
| 四年级 | 关联词与句段关系、中心意思、证据定位、概括与推断、叙事和说明性文本、古诗文理解初步 |
| 五年级 | 复杂句与篇章逻辑、内容概括、人物与景物描写作用、说明方法、跨段推断、传统文化与实际表达 |
| 六年级 | 语言综合运用、多文本信息整合、观点与证据初步、概括评价、古诗文语境理解、真实任务表达 |

### 3.2 数学

| 年级 | 核心知识与能力 |
| --- | --- |
| 一年级 | 数的认识与比较、基本加减、位置与顺序、常见图形、钟表初步、分类统计、一步生活问题 |
| 二年级 | 加减运算、乘除初步、长度时间与人民币、方向和图形、数据分类、一步及简单两步生活问题 |
| 三年级 | 较大数与乘除、分数初步、质量和时间、周长与面积初步、数据表达、两步问题与规律发现 |
| 四年级 | 多位数运算、运算律、小数初步、角与几何关系、平均数与数据分析、多步问题和数量关系 |
| 五年级 | 小数和分数运算、因数与倍数、简易方程、平面图形面积、体积初步、统计与综合应用 |
| 六年级 | 分数百分数、比和比例、圆与空间观念、负数初步、统计与可能性、综合建模和策略选择 |

各年级具体数域和运算复杂度在题目蓝图中设上限；若不同教材的教学时间存在差异，题目只使用全国通用且在该年级结束前通常已经掌握的内容。

### 3.3 英语

| 年级 | 核心知识与能力 |
| --- | --- |
| 一年级 | 字母与声音感知、问候、数字颜色、家庭学校、简单课堂指令、图文匹配 |
| 二年级 | 日常名词和动作、单复数感知、like/have/can 等常用表达、简短问答和生活对话 |
| 三年级 | 句子和短对话阅读、一般现在时基础、疑问词、时间和日常活动、显性信息提取 |
| 四年级 | 连贯短文、方位和频率表达、进行中的动作、比较和描述、跨句信息匹配 |
| 五年级 | 段落阅读、常见时态在语境中的辨析、情境交际、指代与简单推断、信息整理 |
| 六年级 | 多段文本、综合语言功能、关键信息归纳、语境推断、通知日程等真实任务阅读 |

英语考查以理解和使用为主，不以孤立、偏难的语法术语或教材专属词表为核心。低年级题目必须保证仅靠屏幕文字和图片缺失时仍可作答。

## 4. 题量与分布

每个年级、每个学科固定 140 题：

| 维度 | 配额 |
| --- | --- |
| 选择题 | 105（75%） |
| 填空题 | 21（15%） |
| 连线题 | 14（10%） |
| 简单 | 70（50%） |
| 中等 | 49（35%） |
| 困难 | 21（15%） |

题型配额和难度配额是两个独立维度，最终统计必须同时精确满足。每科知识点数量以蓝图为准，任何单一知识点不得超过该科总题量的 20%，且每个核心知识域必须同时包含理解或应用层题目。

105 道选择题的正确选项 A/B/C/D 数量应尽量为 27/26/26/26，任一位置相对 26.25 的偏差不得超过 3。干扰项必须合理、互异，不能通过长度、措辞或固定位置猜答案。

难度定义如下：

- 简单：单一知识点、一步识别或计算，但仍需阅读理解，避免无意义送分题。
- 中等：两步处理、情境转换、信息筛选或易错点辨析。
- 困难：多信息整合、策略选择或迁移推理；不得依赖超纲知识和偏题怪题。

## 5. 标准题目模型

仓库中每题采用完整对象，不再由文件名和默认值隐式补齐关键字段：

```json
{
  "id": "g2-math-multiplication-001",
  "subject": "math",
  "grade": 2,
  "difficulty": 2,
  "type": "choice",
  "knowledgePoint": "表内乘法",
  "skill": "apply",
  "tags": ["生活情境", "两步思考"],
  "content": {
    "stem": "每盒彩笔有6支，3盒一共有多少支？",
    "options": ["9支", "12支", "18支", "24支"],
    "answer": 2,
    "explanation": "每盒6支，3盒就是6×3=18支。"
  },
  "reviewStatus": "approved",
  "version": 1
}
```

`skill` 只允许 `recall`、`understand`、`apply`、`reason`。`reviewStatus` 只允许 `draft`、`reviewed`、`approved`；只有 `approved` 可以生成发布 SQL。`contentHash` 由规范化后的学科、年级、题干、选项和答案自动计算，不由作者手填。

数据库为 `questions` 增加：

- `external_id text not null unique`：仓库中的稳定题目 ID。
- `knowledge_point text not null`：组卷使用的知识点。
- `skill text not null`：能力层次。
- `tags text[] not null default '{}'`：可扩展标签。
- `content_hash text not null unique`：去重和幂等导入依据。
- `review_status text not null`：发布状态。
- `version int not null default 1`：内容修订版本。

`source` 保留，但本阶段发布题统一为 `builtin`。数据库类型定义同步更新。

## 6. 离线题库流水线

### 6.1 文件组织

每个年级、学科一个规范 JSON 文件，例如 `data/questions/grade2-math.json`。另设机器可读的课程蓝图文件，定义允许的知识点、配额和适用标签。仓库 JSON 是唯一需要人工审阅的内容源。

### 6.2 校验顺序

校验脚本在生成 SQL 前依次执行：

1. JSON Schema 和枚举校验。
2. 年级、学科、题型、难度及知识点配额校验。
3. 选择题四个互异选项、答案索引和正确位置均衡校验。
4. 填空题答案去首尾空格、英文小写规范及可接受答案校验。
5. 连线题左右数量、索引范围、一一配对和答案完整性校验。
6. 空题干、空解析、解析未说明关键步骤等内容完整性校验。
7. 规范化题干的精确重复和高相似题干检测。
8. 可机器判断的数学题重新计算或约束校验。
9. 禁用词、教材版本名称、超纲标签和不适龄表达检查。

确定性错误直接使命令失败；近似重复、语言歧义和学段边界问题输出人工审阅报告并阻止发布，直到被明确处理。任何校验失败都不得生成可导入 SQL。

### 6.3 SQL 生成与发布

生成器只读取已通过校验且状态为 `approved` 的题目，生成单独的新迁移文件。迁移按 `external_id` 执行 upsert，并更新内容、元数据、哈希和版本；不删除数据库中其他题目。需要下架的题目必须通过显式下架迁移处理，避免误删用户作答记录引用的题目。

所有 Supabase 地址和密钥只能来自环境变量。现有脚本中的硬编码匿名密钥必须移除。远程导入是显式发布动作，不属于普通构建或测试命令。

## 7. 运行时动态组卷

普通单科练习每次目标 10 题：7 道选择、2 道填空、1 道连线；难度目标为 5 道简单、3 道中等、2 道困难，并覆盖至少 4 个知识点。

组卷流程：

1. 按用户年级和学科读取已批准题目。
2. 读取该用户与候选题相关的历史作答时间。
3. 将题目分为“从未作答”“30 天前作答”“最近 30 天作答”三层。
4. 在满足题型、难度和知识点覆盖的前提下，依次从三层补足；同层优先最久未作答，最后使用受控随机打散。
5. 某个精确格子不足时，按“保持题型，放宽相邻难度；保持总题数，放宽题型”的顺序降级，并记录开发日志，不让页面卡死。

组卷器实现为与网络请求分离的纯函数，以便使用固定候选题和历史记录进行单元测试。Supabase 查询、组卷策略和 Zustand 会话状态分别承担数据获取、规则计算和界面状态管理，避免继续把所有逻辑堆在 `quizStore` 中。

综合挑战按三科各 10 题组成，每科复用相同的组卷规则，最终打乱全局顺序。数独不再固定占数学练习 2 题、挑战 3 题；第一阶段将它作为带有 `思维拓展` 标签的可选题，最多偶尔出现 1 题。若保留前端生成数独，则必须记录为可持久化的正式题目引用或从完成进度口径中明确排除；默认方案是建立静态、可记录的数独题，确保“完成 10 题”与数据库记录一致。

## 8. 现有题库迁移

现有二年级约 839 题先进行自动审计。符合新模型、课程边界和质量规则的题目可迁移进新的 140 题/科首批集合；精确重复、同干换序、答案位置严重偏斜或解析不足的题目不直接发布。其他年级现有约 20 题/科的单一选择题只作为候选素材，必须补齐元数据并通过同样校验。

迁移不会直接覆盖线上题库。顺序为：规范化本地 JSON、生成审计报告、完成修订、测试迁移 SQL、备份线上统计、执行幂等发布、抽样验证。保留被历史作答记录引用的旧题，必要时增加发布状态而非物理删除。

## 9. 错误处理与可恢复性

- 题库为空：显示明确的“该年级题库正在准备”提示，不进入空白答题页。
- 候选题不足：使用预定义降级顺序补足，仍不足则返回可解释错误，不创建残缺会话。
- 历史记录查询失败：允许退化为无历史的配额组卷，但记录错误；题库查询失败则阻止开始。
- 保存作答失败：保留当前完成状态并允许重试，防止重复写入需要由记录幂等键或客户端去重处理。
- 迁移失败：事务整体回滚；不得先清空旧题库。
- 校验失败：输出到具体文件、题目 ID 和规则，不产生发布产物。

## 10. 测试与验收

### 10.1 自动化测试

- 校验器测试：合法的 choice/fill/match 样例通过，各类结构错误、重复、配额错误和答案失衡被拒绝。
- 哈希测试：格式等价内容得到相同哈希，题干或答案变化会改变哈希。
- 组卷器测试：精确满足 7/2/1、5/3/2、至少 4 个知识点和无重复题目。
- 历史策略测试：未做题优先于 30 天前题，30 天前题优先于最近题。
- 降级测试：题库局部不足时仍能按既定顺序组成 10 题；总量不足时返回明确失败。
- Store 集成测试：普通练习和挑战正确建立会话、保存 10/30 条记录，并正确传播加载错误。
- SQL 快照或结构测试：生成结果使用 upsert、不包含全表删除、不包含密钥。

### 10.2 数据验收

第一阶段发布前必须满足：

- 6 个年级 × 3 个学科 × 140 题，共 2,520 题。
- 每个年级学科的题型、难度、知识点和答案位置统计全部通过。
- 精确重复为 0；未处置的近似重复为 0。
- 每题都有非空解析，且选择题没有重复选项。
- 随机抽取每年级每科至少 20 题进行人工审阅。
- 本地全量测试与生产构建通过。
- 在测试数据库执行迁移两次，第二次不增加重复数据。

### 10.3 产品验收

- 同一用户连续多次练习时，最近 30 天题目不会在题量充足时重复。
- 任一次普通练习满足 10 题目标结构，并覆盖至少 4 个知识点。
- 用户完成数学 10 题后，今日统计记录为 10，而不是因临时数独少记。
- 关闭网络或 Supabase 返回错误时，界面可恢复且不会永久加载。
- 浏览器端不存在大模型 API 调用和相关密钥。

## 11. 分阶段交付

为降低一次性生成 2,520 道题带来的审校风险，实施分成可独立验收的阶段：

1. 基础设施：数据模型、课程蓝图、校验器、统计器、幂等 SQL 生成器。
2. 组卷系统：纯组卷器、历史防重复、普通练习与挑战接入、数独记录修复。
3. 二年级试点：从现有题库整理出每科 140 题，完成全量审计与线上验证。
4. 一、三至六年级：按相同标准逐年级补齐并发布，每个年级作为独立数据提交审阅。
5. 扩容准备：根据重复率、正确率和知识点覆盖数据调整规则，再将每年级扩到 840 题。

题库内容提交与系统代码提交分开，便于审查、定位问题和回滚。任何阶段都不以降低校验标准换取题量。
