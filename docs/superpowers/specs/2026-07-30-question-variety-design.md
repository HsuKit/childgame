# 三年级题目多样性设计

## 背景

三年级线上每科有 140 道 approved 题且题干唯一，但连续练习仍会产生明显重复感。根因分为三类：

1. 结果页“再练一组”只导航，不替换已完成会话。
2. 组卷器优先满足精确题型和难度，再考虑作答历史；小配额池会在其他未做题仍充足时提前重复。
3. 题库重复审计只识别完全相同或高文本相似题干，无法识别换数字、姓名和场景的同模板题。

## 目标与验收

- “再练一组”在结算成功后创建新会话。
- 同一用户、同一科目前 10 轮共 100 题，在可组合题型总量充足时不重复题目 ID。
- 每组 10 题至少覆盖 6 个知识点和 8 个内容模板，同一模板不超过 2 题；题库不足时允许有明确的降级结果。
- 已做过的精确难度题与未做过的相邻难度题冲突时，优先未做题。
- 三年级 canonical 题目全部带稳定的 `模板:<key>` 标签，发布审计拒绝缺失模板标签或模板过度集中。
- 运行时继续只读取 Supabase 静态题库，不调用 AI。

## 方案

### 新会话

结果页在结算状态为 `success` 后才允许“再练一组”。点击时直接调用 store 的 `startSession(subject)` 替换旧会话，成功后再导航到答题页；失败时保留结果页并显示错误状态，避免丢失已完成记录。

### 跨轮次避重

组卷器把候选池分为“未做”和“已做”。每个槽位按以下顺序选择：

1. 精确题型与难度的未做题；
2. 同题型的未做题；
3. 同难度的未做题；
4. 任意未做题；
5. 精确、同题型、同难度、任意已做题。

这让题库覆盖优先于严格难度配额。只有所有可组合题都做过后，才按最久未做顺序复用。

### 模板多样性

canonical JSON 继续使用现有 `tags`，增加且只增加一个 `模板:<key>` 标签。key 表示解题结构，不表示具体数字或人物。组卷时优先尚未在当前题组出现的模板；无法满足时允许同模板最多出现两题，再继续降级。

三年级作者脚本为语文、数学、英语生成模板标签，并扩大数学和英语的题干结构变体。语文把共用短文、修辞和应用文等结构分别标记，避免同一短文在一组内反复出现。

### 离线门禁

schema 要求三年级 approved 题恰好有一个合法模板标签。audit 统计模板分布，并在以下情况阻止发布：

- 缺失或重复模板标签；
- 单一模板占本学科题库比例超过配置阈值；
- 可用于 10 题组卷的模板少于 10 个。

发布仍走 canonical JSON → release manifest → 新 migration → Supabase upsert。

## 验证

- Vitest：新鲜题优先、连续 10 轮无 ID 重复、模板覆盖及降级、结果页重新组卷。
- Node tests：模板标签 schema、模板集中度审计、三年级 420 题作者与发布校验。
- 全量：`npm test`、`npm run test:questions`、`npm run questions:validate`、`npm run docs:check`、`npm run build`。
- 远端：迁移后核对三年级每科 140 approved、140 唯一 external_id、模板标签完整，并做线上连续组卷抽样。
